El sistema open source de subtítulos simultáneos para conferencias

Simulcast es un sistema completo —no una librería— para producir subtítulos en vivo en decenas de escenarios en paralelo: recibe el audio de un escenario (OBS por RTMP o el audio de tu navegador), lo transcribe y traduce en tiempo real con la Gemini Live API, y lo entrega a la audiencia web, al overlay de OBS y a cualquier cliente por API. Código abierto bajo licencia Apache-2.0: self-hosted, sin vendor lock-in.

Qué hace

Transcripción en vivo

El audio del escenario se transcribe en el idioma hablado, con parciales (interim) y finales, en menos de un segundo.

Traducción simultánea

Cada sesión entrega original + traducción (es / en / pt). La audiencia elige el idioma que quiere ver.

Multi-escenario

Diez o más sesiones en paralelo, cada una con su stream, sus workers y su página de subtítulos.

Dos fuentes de audio

OBS → RTMP para producción, o audio del navegador (pestaña o micrófono) para probar sin infraestructura.

Quemar en el stream

La página /overlay es un Browser Source transparente para OBS, vMix o Streamlabs: subtítulos dentro del video.

Operación y monitoreo

Panel de operación para el audio y panel de monitoreo con latencia, rates y errores en vivo para el equipo de producción.

Cómo funciona

OBS / RTMP ──► MediaMTX ──► ffmpeg (PCM 16 kHz) ──┐
                                                   ├──► Session Manager ──► Gemini Live workers
Navegador (pestaña / micrófono) ──► WS /ws/ingest ─┘                              │
                                                                                  ▼
                              Audiencia ◄── WS /ws/captions ◄── EventBus
                              (elegir sesión + idioma)

1. Entrada de audio

RTMP desde OBS (un path por sesión: rtmp://host:1935/main) o el navegador enviando PCM 16 kHz mono por WebSocket.

2. Workers por sesión

Cada sesión con traducción abre una conexión a la Gemini Live API. Arrancan con el primer audio y se detienen ~60 s después de que el stream muere (ahorra cuota).

3. Salida para la audiencia

Un fan-out por WebSocket lleva captions a la vista web, al overlay de OBS y a cualquier cliente que se conecte. La API key nunca sale del servidor.

Cómo usar Simulcast

Demo en 60 segundos

  1. Creá una sesión en Operación (ej. origen en, traducción es).
  2. Marcá una o varias sesiones y tocá Compartir audio (pestaña con audio o micrófono).
  3. Abrí el programa: la sesión pasa a en vivo y los subtítulos fluyen en vivo.

En producción (OBS)

  1. OBS → Settings → Stream → Custom: rtmp://TU_HOST:1935, stream key = id de la sesión.
  2. Verificá en Operación que el audio esté activo.
  3. Para quemar subtítulos en el video: Browser Source con /overlay?session=….

Vistas del sistema

  • /program — grilla del programa y vista de audiencia.
  • /operator — crear sesiones y compartir audio.
  • /monitor — panel de producción (latencia, rates, errores).
  • /overlay — subtítulos para OBS / vMix.

Referencia de la API

Todo el sistema se opera por HTTP + WebSockets. La misma instancia expone OpenAPI en /docs (Swagger) para probarla en el navegador. Los endpoints de escritura hoy no llevan auth (pensados para LAN/VPN del evento): la autenticación por sesión está en el roadmap.

Endpoints REST

MétodoRutaDescripción
GET/api/healthEstado general: sesiones, rates, uptime, modelos, Gemini configurado
GET/api/monitorSnapshot de monitoreo: sesiones + métricas + errores recientes
GET/api/monitor/errorsÚltimos errores (parámetro ?limit=)
GET/api/sessionsLista de sesiones con workers, ingest y métricas
GET/api/sessions/{id}Snapshot de una sesión (404 si no existe)
POST/api/sessionsCrear sesión (201 · 429 si se supera el máximo · 422 si es inválida)
PUT/api/sessions/{id}Reconfigurar (reinicia sus workers)
DELETE/api/sessions/{id}Eliminar sesión (204)
GET/api/sessions/{id}/captions?lang=esHistorial de captions (lang=all para todos)
GET/api/sessions/{id}/export.{fmt}?lang=…Export: srt · vtt · txt

Crear una sesión

curl -X POST http://localhost:8000/api/sessions \
  -H 'Content-Type: application/json' \
  -d '{
    "id": "main",
    "name": "Main Stage",
    "source_language": "en",
    "output_languages": ["original", "es"]
  }'

Campos: id (slug), name, source_language (en | es | pt | auto), output_languages (siempre arranca con original).

Estado y salud

curl -s http://localhost:8000/api/health | jq
curl -s http://localhost:8000/api/sessions | jq '.sessions[].config.id'

Ideal para scripts y alertas: gemini_configured, live_sessions, captions_per_min, errors_total, uptime_s.

Captions y export

curl 'http://localhost:8000/api/sessions/main/captions?lang=es'
curl -OJ 'http://localhost:8000/api/sessions/main/export.vtt?lang=es'

El historial vive en memoria: consultalo durante el evento o exportá al final de cada charla.

WebSockets

RutaDirecciónQué hace
/ws/captions/{id}?lang=esaudienciaStream de subtítulos (lang=all para todos los idiomas). Primer mensaje hello con el estado de la sesión.
/ws/ingest/{id}operadorAudio entrante: frames binarios PCM s16le mono 16 kHz de 100 ms (3200 bytes). Responde {"type":"ready"} al abrir.
/ws/monitorpanelSnapshot inicial + actualizaciones de estado y heartbeat cada 3 s.

Formato de un caption (JSON)

{
  "type": "caption",
  "session": "main",
  "lang": "es",
  "text": "Hola, bienvenidos a la conferencia",
  "final": true,
  "t": 1769000000.123,
  "id": "main:es:42:ab12cd"
}

Los eventos con final:false son parciales (interim): la UI los reemplaza cuando llega el final con el mismo id.

Proyecto open source

Licencia Apache-2.0

Aprobada por la Open Source Initiative. Usalo, modificalo y distribuilo en tu evento — incluso comercialmente — conservando la licencia y el copyright.

Self-hosted, sin vendor lock-in

Corre en tu servidor (Docker o Python). Tu GEMINI_API_KEY nunca sale de tu instancia y los datos del evento quedan donde vos los pongas.

Transparente por diseño

Todo el sistema es HTTP + WebSockets documentado abajo, con OpenAPI en /docs. Sin cajas negras: podés leer el código de cada worker.

Contribuciones bienvenidas

Issues y pull requests en github.com/anchundiatech/Simulcast. Hecho para la Vibeathon de Nerdearla.

Roadmap

Lo que ya está y lo que viene. El orden es orientativo y puede cambiar según la comunidad.

  • hecho Transcripción + traducción en vivo multi-sesión (RTMP y navegador)
  • hecho Vista de programa público, overlay OBS/vMix y panel de monitoreo
  • hecho Export SRT / VTT / TXT por sesión e idioma
  • próximo Glosario de términos del evento vía custom_vocabulary
  • próximo Latencia p50/p95 y costos estimados en el panel de monitoreo
  • próximo Auth por sesión — tokens para /ws/ingest y la API de operación, y tokens efímeros de Gemini para clientes (hoy la API key vive solo en el servidor y el ingest debe restringirse por red; ver docs/DEPLOY.md §8)
  • después Portugués y más idiomas de salida (workers de translate adicionales)
  • después Caller SRT/ffmpeg para quemar subtítulos sin Browser Source

Despliegue

Docker (recomendado)

git clone <repo-url> simulcast && cd simulcast
cp .env.example .env            # GEMINI_API_KEY=...
cp sessions.example.yaml sessions.yaml
docker compose up -d --build
curl -s http://localhost:8000/api/health | jq

Requisitos

  • Una API key de Google AI Studio.
  • Python 3.11+ o Docker; ffmpeg + MediaMTX solo si usás RTMP.
  • 2 vCPU / 4 GB RAM alcanzan para la demo; el peso lo lleva la Gemini Live API.
  • Guía completa: docs/DEPLOY.md (TLS, MediaMTX, overlay, seguridad).
