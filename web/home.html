Una transmisión no debería tener un solo idioma.

Los eventos internacionales tienen una barrera invisible: el idioma. Las traducciones manuales son costosas y difíciles de escalar, mientras que las soluciones cerradas pueden ser difíciles de adaptar a diferentes flujos de producción.

01

Un idioma limita la audiencia

Una charla en inglés puede dejar fuera a gran parte de la audiencia.

02

Muchos escenarios complican la operación

Los eventos grandes necesitan procesar múltiples sesiones simultáneamente.

03

El tiempo importa

Los subtítulos deben aparecer mientras la persona está hablando, no varios minutos después.

Referencia de la API

Todo el sistema se opera por HTTP + WebSockets, con OpenAPI en /docs. Los endpoints de escritura hoy no llevan auth (LAN/VPN del evento): la auth por sesión está en el roadmap.

REST

  • GET /api/health
  • GET /api/monitor
  • GET /api/sessions
  • POST /api/sessions
  • PUT /api/sessions/{id}
  • DELETE /api/sessions/{id}
  • GET /api/sessions/{id}/captions
  • GET /api/sessions/{id}/export.vtt

WebSockets

  • /ws/captions/{id} — stream de subtítulos
  • /ws/ingest/{id} — audio entrante
  • /ws/monitor — snapshots de producción

Crear sesión

curl -X POST /api/sessions \
  -H 'Content-Type: application/json' \
  -d '{"id":"main","name":"Main Stage",
       "source_language":"en",
       "output_languages":["original","es"]}'
